# AI_LOG — работа с ИИ над проектом

## Инструменты и модель

Все этапы выполнялись в OpenCode. В качестве модели использовалась Qwen3.8 (27B) через Ollama. Ассистент писал код по частям: сначала инфраструктура (Docker, тестовая БД), затем модели/миграции, schemas, эндпоинты и в конце документация.

## Ключевые запросы

1. Сперва дал задание проанализировать pdf с тестовым и переделать его в .md файл, что бы в дальнейшем исключить этот шаг и читать сразу из .md:
```bash
  Проанализируй @Тестовое_Junior_Python_FastAPI.pdf и составь из него текстовый вариант в формате .md (TASK.md)
```

2. Далее дал задание составить подробный план реализации всех требований из тестового:
```bash
    Проанализируй тестовое задание @TASK.md и предоставь подробный план его выполнения. В качестве пакетного менеджера будет использоваться uv. План составляй с учетом всех требований включая бонусные. Учитывай все нюансы работы с платежами (атомарность, блокировки, идемпотентность). База данных только Postgres. В PLAN.md подробно распиши каждый шаг (каждый будет реализовываться в отдельной сессии)
```

3. Далее для каждой сессии писал запрос вида:
```bash
    Изучи @TASK.md и @PLAN.md и реализуй пункт S1 из @PLAN.md, следуй указаниям из этого пункта, не придумывай лишнего, в конце предоставь отчет по выполненной работе.
```
## Где модель ошиблась или предложила слабое решение

- Первые тесты модель написала в синхронном варианте хотя драйвер для бд asyncpg и используется AsyncSession. Модель написала костыли для того, чтобы правильно выполнять асинхронные операции внутри синхронных pytest-тестов через client.portal.
